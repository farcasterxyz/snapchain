# Getting Started

:::tip
If your goal is to get started as quickly as possible, consider a managed service like [Neynar](https://neynar.com/) instead of running your own node.
:::

## Requirements

- 16 GB of RAM
- 4 CPU cores or vCPUs
- 2 TB of free storage
- A public IP address with ports 3381 - 3383 exposed

## Sync a node

The easiest way to run Snapchain is with the install script, which runs the node under [Docker](https://www.docker.com/get-started/) and installs Docker for you if it is missing:

``` bash
curl -sSL https://raw.githubusercontent.com/farcasterxyz/snapchain/refs/heads/main/scripts/snapchain-bootstrap.sh | bash
```

The script installs everything into `~/snapchain`, whichever directory you run it from. It asks you to confirm that you will not receive rewards for running a node and for your FID, then starts the node and follows its logs. See [Manage a node with snapchain.sh](/guides/managing-a-node) for what each step does and how to start, stop and upgrade the node later.

Check the logs to make sure the snapshot is downloading:

``` bash
curl -s localhost:3381/v1/info | jq
```

`blockDelay` is how many seconds each shard's newest block is behind the current time. While the node catches up it counts down; once every shard is in the single digits, the node is in sync. `maxHeight` differs between shards because each shard is its own chain. On a read node `mempoolSize` reads `4294967295` for shards 1 and 2, which means "not reported" (see [Validators vs. read nodes](/node-types#mempool)).

## Query a node

Once the node is in sync you can start querying it for the latest messages from a user. You'll need the user's account id to get their messages. If you don't have this handy, you can do a lookup by username from the public Farcaster name server. 

```bash
# Query for the id associated with the @farcaster account
curl https://fnames.farcaster.xyz/transfers?name=farcaster

{
  "transfers": [
    {
      "id": 1,
      "timestamp": 1628882891,
      "username": "farcaster",
      "owner": "0x877...06ed",
      "from": 0,
      "to": 1,
      "user_signature": "0xa6fdd...471b",
      "server_signature": "0xb718...c41b"
    }
  ]
}
```

The `@farcaster` user's account id is 1, and so you can fetch the latest messages by querying the node over its [HTTP API](/reference/httpapi/httpapi):

```
curl http://localhost:3381/v1/castsByFid\?fid\=1 \
 | jq ".messages[].data.castAddBody.text \
 | select( . != null)"
```
